## 二、核心技术栈与面试考点

### 2.1 后端核心技术

| 技术 | 用途 | 面试考点 |
|------|------|---------|
| Spring Boot 3.x | 应用框架 | 自动配置原理、条件注解、启动流程 |
| Spring Cloud Alibaba | 微服务 | 服务发现、配置中心、负载均衡 |
| Spring Cloud Gateway | API网关 | 路由断言、过滤器链、跨域 |
| MyBatis-Plus | ORM | 分页、乐观锁、代码生成器 |
| MySQL 8.0 | 关系型数据库 | 索引优化、SQL调优、事务隔离级别 |
| Redis 7 | 缓存 | 缓存穿透/击穿/雪崩、分布式锁 |
| Elasticsearch | 搜索引擎 | 倒排索引、分片、聚合查询 |
| RabbitMQ | 消息队列 | 死信队列、延迟队列、消息可靠投递 |
| Seata | 分布式事务 | AT模式、TCC模式、XA模式 |
| Sentinel | 限流熔断 | 滑动窗口、漏桶/令牌桶 |
| ShardingSphere | 分库分表 | 水平分片、读写分离 |

### 2.2 面试高频问题覆盖

**分布式事务（Seata）：**
- AT模式：自动生成UNDO_LOG，业务无侵入
- TCC模式：Try-Confirm-Cancel，需要业务方实现
- 适用场景对比：AT适合大多数场景，TCC适合高性能场景

**高并发设计：**
- 缓存策略：多级缓存（Caffeine + Redis）
- 消息队列削峰：RabbitMQ异步处理OCR/通知
- 数据库优化：索引设计、读写分离、分库分表
- 限流降级：Sentinel QPS限流、线程隔离

**消息队列（RabbitMQ）：**
- 死信队列：处理超时未支付订单
- 延迟队列：定时通知、定时任务
- 可靠投递：Confirm机制 + 手动ACK
- 顺序消费：同一队列绑定到同一消费者

## 三、数据库设计

见 `sql/init.sql`，核心表：
- `user` — 用户表（含角色、学币）
- `question` — 题目表（含全文索引）
- `category` — 分类表（树形结构）
- `user_answer` — 答题记录表
- `favorite` — 收藏表

## 四、部署架构

### 4.1 单体部署（阶段1）
```
Nginx → Spring Boot App(8080) → MySQL + Redis
```

### 4.2 微服务部署（阶段3）
```
Nginx → Spring Cloud Gateway → 服务实例池 → MySQL集群 + Redis + ES + RabbitMQ
                              ├── user-svc(2副本)
                              ├── question-svc(2副本)
                              ├── search-svc(2副本)
                              ├── ai-svc(1副本)
                              └── ...
```

## 五、性能优化要点

| 场景 | 优化方案 |
|------|---------|
| 热点题目 | Redis缓存 + Caffeine本地缓存 |
| 搜题慢 | Elasticsearch代替MySQL全文检索 |
| 高并发 | Sentinel限流 + RabbitMQ削峰 |
| 数据库压力 | 读写分离 + 分库分表 |
| 图片存储 | MinIO对象存储 + CDN |
| 接口响应 | 异步处理(@Async) + 并行流 |
